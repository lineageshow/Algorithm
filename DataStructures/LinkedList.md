# Linked List（鏈結串列）資料結構詳解

---

## 一、定義與特性

**Linked List（鏈結串列）** 由一連串 **節點（node）** 組成；每個節點通常包含 **資料** 與 **指向下一節點的指標**（單向鏈結）。**雙向鏈結（Doubly Linked List）** 另含 **指向前一節點的指標**，便於在已知節點處 O(1) 刪除。

| 類型 | 說明 |
|------|------|
| **Singly Linked List** | 僅 next 指標，結構簡單 |
| **Doubly Linked List** | 有 prev、next，刪除／插入較彈性，多一點空間 |

與 **陣列** 相比：鏈結串列 **不保证** 節點在記憶體中連續，插入／刪除已知節點可 O(1)（若已持有指標）；**不支援** O(1) 隨機存取第 k 個元素（需從頭走訪）。

---

## 二、核心操作與複雜度

以下為單向鏈結常見操作（需否先找到位置另計）：

| 操作 | 時間 | 備註 |
|------|------|------|
| 在 **已知節點** 後插入 | O(1) | |
| 刪除 **已知節點**（雙向較直觀） | O(1) | 單向刪除常需前驅 |
| 在頭端插入 | O(1) | |
| 依 **值或索引** 搜尋 | O(n) | 需走訪 |
| 走訪全部 | O(n) | |

空間：**O(n)** 節點。

---

## 三、使用情境

| 情境 | 說明 |
|------|------|
| **頻繁在頭端插入／刪除** | 避免陣列搬移 |
| **總長度變動大** | 不需預先宣告固定容量 |
| **實作其他結構** | 如 LRU Cache（常雙向鏈結 + HashMap） |
| **不強求隨機存取** | 以循序存取為主 |

不適合：需要 **依索引頻繁 O(1) 讀寫** 時，陣列較佳。

---

## 四、適合搭配的演算法與題型

| 類型 | 範例 |
|------|------|
| 指標技巧 | 反轉鏈結（Reverse Linked List） |
| 快慢指針 | 偵測環（Linked List Cycle）、找中點 |
| 合併 | Merge Two Sorted Lists |
| 重排／分割 | 奇偶重排、Partition List |
| 數學／進位 | 兩數相加（Add Two Numbers） |

與 **Stack** 的關係：反轉或比對時可暫用堆疊輔助；亦可用指標直接改寫 next，見 [Stack](Stack.md)。

---

## 五、小結

鏈結串列適合 **插入刪除頻繁、不需隨機存取** 的建模。解題時常見 **dummy node**（哨兵節點）簡化邊界，以及 **快慢指針** 處理環與中點問題。
